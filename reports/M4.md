# M4 — Performance foundation

## What landed

Neighbor rebuilds now stable-sort atoms by a 10-bit Morton code of the cell and permute every per-atom array. `gid` records the original index. Position, velocity, and force downloads scatter back to that index. Neighbors are sorted by global id, so the pair sum stays in the oracle's order.

`Run` sets `need_rebuild` on the device from a block-reduced minimum-image displacement, or from `rebuild_every_step`. The permute, cell-fill, and neighbor kernels return immediately when that flag is clear. Fifty steps are captured in one CUDA graph and replayed. The host synchronizes and reads `DeviceStatus` every 1000 steps. A device snapshot covers positions, velocities, images, types, and global ids; an overflow restores it, grows the list, recaptures the graph, and reruns the segment. CUB's radix sort has no early-exit prologue, so it is inside the graph every step and ignored unless a rebuild was requested. Templated energy and virial, and conditional graph nodes, are not in yet.

## Tests

`BUILD_DIR=build-m4 bash scripts/check.sh` compiled this engine, including the graph replay, and passed the two CPU tests (2026-10-19). The GPU suite was not repeated: the M3 radial-distribution and drift jobs are using this GPU. Those tests still have to pass on this binary before G2 or G3 can be claimed.
