# M2 — CPU reference oracle

## What was built

A double-precision LJ reference in `reference/lj_reference.cpp`. It is the pair loop from PLAN.md section 4.1: every ordered pair, `std::rint` minimum image, and the `inv_r2` / `sr6` evaluation. `tilemd_make_fixtures` writes the fixtures. The CPU tests cover an analytic pair, both shift modes, the cutoff, minimum image, momentum, fixture round-trips, and the LAMMPS comparison.

## Gate G1-ref

LAMMPS 22 Jul 2025 Update 4, CPU (not KOKKOS), `pair_style lj/cut 2.5`, `pair_modify shift no`. The snapshot is an fcc melt, `N = 4000`, `rho = 0.8442`, `T = 1.44`, seed `12345`, `dt = 0.005`, 1000 NVE steps. Input: `tests/validation/lammps_ref/in.melt_4000`.

Under `units lj`, LAMMPS divides the `pe` thermo column by `N`. The virial columns are user variables and are not rescaled. The comparison uses the total energy `pe * N`.

| Quantity | Relative discrepancy |
|---|---|
| Forces, `max_i |F_ref - F_LAMMPS| / rms(|F_LAMMPS|)` | `6.7e-14` |
| Potential energy | `3.2e-16` |
| Virial, six components, max relative | `4.8e-14` |

The gate is `1e-10`. It passes. `fcc_500` maximum force component is `2.5e-14`.

## Fixtures

Each JSON is under 1 MB. `melt_4000` positions come from the LAMMPS dump, wrapped into the box. The other six are generated by the reference.

| Fixture | N | Role |
|---|---|---|
| `fcc_500` | 500 | perfect fcc, `rho = 0.8442`, force cancellation |
| `melt_4000` | 4000 | equilibrated LJ melt |
| `boundary_500` | 500 | atoms within `1e-3` of faces, edges, and corners |
| `cutoff_500` | 500 | dimers at `r_c ± 1e-4` |
| `twotype_2000` | 2000 | explicit pair table, no mixing rule |
| `dilute_1000` | 1000 | `rho = 0.05` |
| `dense_2000` | 2000 | `rho = 1.2` |

## Deviations

- The oracle uses `std::rint` rather than `rintf`. `rintf` would round the double coordinates. The float kernel in later milestones still follows decision D10.
- There is no cell-list path. Every fixture has `N <= 4000`, which is the brute-force case in the plan.
