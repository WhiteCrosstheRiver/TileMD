# M6 — Fused single-kernel time step

## What is in

`reference/lj_reference.cpp` now steps the double-precision oracle with velocity Verlet and with leapfrog. Leapfrog keeps `v(t − dt/2)`. The conversion from an integer-time start is `v(−dt/2) = v(0) − ½ dt f(0) / m`. Integer-time velocity for comparison is `v(t) = v(t − dt/2) + ½ dt f(t) / m`. Positions wrap into the box and image counters record the periods.

`RunFusedTileLeapfrog` is the GPU step used when `use_cluster_tiles` is set. One warp owns one i-cluster, as in the M5 force kernel. The owning lane adds `dt f / m` to `v(t − dt/2)`, advances and wraps `x`, and writes the other `pos4` buffer. Neighbor coordinates come from the cluster snapshot built on the host at the start of the step, not from `pos4`. The first `Run` converts `v(0)` with one force evaluation. The force array is not read during the fused step. The atom-neighbor engine still uses velocity Verlet.

## What was run

On 40 atoms, `dt = 0.005`, mass 1, for 100 steps, the CPU leapfrog and velocity Verlet stay within round-off. The largest position difference is `8.88e-16`. The largest integer-time velocity difference is `2.11e-15`. Image counters match.

`BUILD_DIR=build-m6 bash scripts/check.sh` compiles the fused kernel and passes the CPU suite. The kernel has not been launched: the 32k RDF and drift runs still occupy the RTX 3050. Bytes per atom-step and the speed comparison with M5 are not measured.
