# M6 — Fused single-kernel time step

## What is in

`reference/lj_reference.cpp` now steps the double-precision oracle with velocity Verlet, leapfrog, and BAOAB Langevin. Langevin draws three standard normals from Philox4x32-10 with counter `(gid, step low, step high, 0)` and key `(seed, 0)`. Zero friction calls velocity Verlet. Zero temperature multiplies the free-particle velocity by `e^{−γ t}`. The device kernel does not apply this thermostat. Leapfrog keeps `v(t − dt/2)`. The conversion from an integer-time start is `v(−dt/2) = v(0) − ½ dt f(0) / m`. Integer-time velocity for comparison is `v(t) = v(t − dt/2) + ½ dt f(t) / m`. Positions wrap into the box and image counters record the periods.

`RunFusedTileLeapfrog` is the GPU step used when `use_cluster_tiles` is set. One warp owns one i-cluster, as in the M5 force kernel. Pair coordinates are loaded from the current `pos4` buffer and promoted to double. The owning lane adds `dt f / m` to `v(t − dt/2)`, advances and wraps the double-precision `x`, and writes the other `pos4` buffer. The cluster list that selects those neighbors is still built on the host from the double-precision positions. The device copy is reused until `rebuild_every_step` is set or the maximum minimum-image displacement exceeds `(skin/2)^2`. The default of that flag is true, so a default run still rebuilds every step. The first `Run` converts `v(0)` with one force evaluation. The force array is not read during the fused step. On a thermo step the same kernel keeps the potential and virial and writes one partial per cluster. The kinetic energy is `½|v(t)|²` with `v(t) = ½(v(t−dt/2) + v(t+dt/2))`, the integer time of the positions the force used. A later one-thread kernel adds the partials into the thermo ring. After the last step, one extra force evaluation records that final integer time, because the positions have moved and the kernel that would see them has not run. Steps that are not thermo steps skip the energy and virial. The atom-neighbor engine still uses velocity Verlet, and this fused thermo path has not been launched.

## What was run

On 40 atoms, `dt = 0.005`, mass 1, for 100 steps, the CPU leapfrog and velocity Verlet stay within round-off. The largest position difference is `8.88e-16`. The largest integer-time velocity difference is `2.11e-15`. Image counters match.

On the 32k melt (`rc = 2.5`, skin `0.3`, 4264 clusters, 329108 cluster pairs) one fused step touches 69219396 bytes of distinct global addresses, 2163.1 bytes per atom. That count is the kernel's own loads and stores with the list already on the device: each real slot's `pos4`, each neighbor cluster's types, gids, and `pos4`, the CSR row, and the owning atom's double `x`, `v`, image counters, reference `pos4`, and the next `pos4`. Padding slots skip `pos4`. Four lanes that share one i-slot are counted once. It is not an Nsight `dram__bytes` measurement, and the kernel has not been launched. The §1.2 target of about 60–110 bytes per atom-step assumed the neighbor coordinates stayed on chip. They do not: about 9% of the visited pairs are inside the cutoff, and each kept cluster reloads eight `pos4` values. A rebuild also copies the list to the device, 91.3 bytes per atom on this configuration. The default `rebuild_every_step` flag does that copy every step.

`BUILD_DIR=build-m8 bash scripts/check.sh` compiles the fused kernel and passes the CPU suite. The kernel has not been launched: the 32k drift run still occupies the RTX 3050. The speed comparison with M5 is not measured.

Rounding every coordinate to binary32 and promoting it back, which is what a `pos4` load does, changes the melt force before the kernel runs. On `melt_4000` the relative force error against the double-precision oracle is `5.81e-5`. That is outside the T1 tolerance of `1e-5`. The forces-only tile kernel still reads the double-precision slot coordinates, so this miss belongs to the fused step, not to that debug kernel. On the 40-atom box the same rounding, used only for the force inside 100 leapfrog steps, moves positions by at most `5.69e-8`. The small box does not stand in for the melt.
