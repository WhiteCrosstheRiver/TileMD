# M6 — Fused single-kernel time step

## What is in

`reference/lj_reference.cpp` now steps the double-precision oracle with velocity Verlet and with leapfrog. Leapfrog keeps `v(t − dt/2)`. The conversion from an integer-time start is `v(−dt/2) = v(0) − ½ dt f(0) / m`. Integer-time velocity for comparison is `v(t) = v(t − dt/2) + ½ dt f(t) / m`. Positions wrap into the box and image counters record the periods.

`RunFusedTileLeapfrog` is the GPU step used when `use_cluster_tiles` is set. One warp owns one i-cluster, as in the M5 force kernel. Pair coordinates are loaded from the current `pos4` buffer and promoted to double. The owning lane adds `dt f / m` to `v(t − dt/2)`, advances and wraps the double-precision `x`, and writes the other `pos4` buffer. The cluster list that selects those neighbors is still built on the host from the double-precision positions. The device copy is reused until `rebuild_every_step` is set or the maximum minimum-image displacement exceeds `(skin/2)^2`. The default of that flag is true, so a default run still rebuilds every step. The first `Run` converts `v(0)` with one force evaluation. The force array is not read during the fused step. The atom-neighbor engine still uses velocity Verlet.

## What was run

On 40 atoms, `dt = 0.005`, mass 1, for 100 steps, the CPU leapfrog and velocity Verlet stay within round-off. The largest position difference is `8.88e-16`. The largest integer-time velocity difference is `2.11e-15`. Image counters match.

`BUILD_DIR=build-m6 bash scripts/check.sh` compiles the fused kernel and passes the CPU suite. The kernel has not been launched: the 32k RDF and drift runs still occupy the RTX 3050. Bytes per atom-step and the speed comparison with M5 are not measured.

Rounding every coordinate to binary32 and promoting it back, which is what a `pos4` load does, changes the melt force before the kernel runs. On `melt_4000` the relative force error against the double-precision oracle is `5.81e-5`. That is outside the T1 tolerance of `1e-5`. The forces-only tile kernel still reads the double-precision slot coordinates, so this miss belongs to the fused step, not to that debug kernel. On the 40-atom box the same rounding, used only for the force inside 100 leapfrog steps, moves positions by at most `5.69e-8`. The small box does not stand in for the melt.
