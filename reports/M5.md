# M5 — Cluster-pair tiles

## What is in

`src/neighbor/cluster_list.cpp` builds the column grid and the cluster-pair list on the host. Columns are an x–y grid with about 32 atoms each when the count is left at zero. Atoms in a column are stable-sorted by z and padded to a multiple of 8. Padding uses type `-1` and does not enlarge the bounding box. A pair of clusters is kept when the periodic box distance is below the reach. The shift index stores the image in `{-1, 0, 1}` on each axis.

`ComputeTileForces` evaluates full-list Lennard-Jones on that list, in cluster order, and writes forces back in the original atom order.

`src/md/tile_force.cu` runs the same pairs on the GPU. One warp owns one i-cluster. Lane `i_local + 8 * j_sub` holds i-atom `i_local` and, for each group of four j-clusters, the j-atom with that local index. The eight j-atoms are broadcast with warp shuffles, including the stored image shift. The four j-sub partials are added in order 0, 1, 2, 3. `HostSystem::use_cluster_tiles` sends `ComputeForces` and velocity Verlet down this path. The atom-neighbor engine stays the default. The cluster list is rebuilt on the host at every force call. Device thermo is not produced on the tile path.

## What was run

`BUILD_DIR=build-m5 bash scripts/check.sh` passed the CPU suite (2026-10-19). That includes the cluster-list tests and a 40-atom shifted-force comparison against the double-precision oracle.

Tile efficiency is pairs with `r < rc` divided by pairs the tile loop computes, with `rc = 2.5` and skin `0.3`:

| System | Pairs inside cutoff | Pairs computed | Efficiency |
|---|---:|---:|---:|
| `melt_4000` | 532162 | 23238166 | 0.0229 |
| 32k LJ melt, initial dump | 5091115 | 595489064 | 0.0085 |

The plan expected about 40–60%. The shortfall is geometric. A column holds about 32 atoms, so an 8-atom cluster is a z-slice several cutoffs long. The bounding-box test keeps that whole slice, and most of its atom pairs are outside `rc`. A wider column, sized so eight atoms fill a cube, stayed near 0.02 and the stencil double-counted pairs, so the 32-atom grid remains.

The GPU comparison `GpuLj.ClusterTileMatchesOracle` is compiled with the GPU test binary. It has not been launched: the 32k RDF and drift runs still occupy the RTX 3050. Bytes per atom-step and the speed comparison with M4 are not measured.
