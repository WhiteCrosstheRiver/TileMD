# M8 — Pair-attention API and EAM

## What is in

`EvaluateAttention` walks a full pair list once per pass. For each ordered pair the potential returns a force scalar `s`, a pair energy, and a value that is summed onto the i atom. The force is rebuilt as `r_i (Σ s) − Σ s r_j`, using the periodic image of `r_j`. `AtomUpdate` runs after the pass, so the next pass can read what it stored.

Lennard-Jones is one pass. The scalar is the same `s(r²)` as the double-precision oracle, including the energy and force shifts. EAM is two passes on a funcfl table. Pass 0 sums the electron density. Pass 1 uses `s = −[(F'(ρ_i) + F'(ρ_j)) ρ'(r) + φ'(r)] / r`. The table is splined with the LAMMPS cubic used by `pair_style eam`, and `r φ(r)` is `27.2 × 0.529 × Z(r)²`. Distances are Angstrom and energies are eV. The Lennard-Jones fixtures stay in reduced units.

## What was run

`BUILD_DIR=build-m8 bash scripts/check.sh` passes the CPU suite.

On `fcc_500`, `boundary_500`, `cutoff_500`, `twotype_2000`, and `melt_4000`, the Lennard-Jones path matches the oracle. Where the reference force is not round-off, the relative force error is below `1e-10`, and the energy and virial agree at the same level. `fcc_500` is checked by absolute residual because its net force is numerical noise.

Cu with `tests/potentials/Cu_u3.eam` (Foiles, the LAMMPS funcfl) on a 3×3×3 fcc cell, one atom displaced, against LAMMPS 22 Jul 2025 Update 4, `pair_style eam`, metal units, 1 OpenMP thread: relative force error `1.45e-13`. Both total energies are `-382.082246` eV. A four-atom finite difference of that energy matches the force component to the test tolerance. The reference rows are `tests/validation/lammps_ref/cu_u3_108.txt`.

## Gate

EAM correctness against LAMMPS is in. G5 is not met: there is no GPU pair-attention kernel, so the overhead against the M6 kernel was not measured. NVE drift and the KOKKOS EAM benchmark were not run.
